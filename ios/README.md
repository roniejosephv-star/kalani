# Native iPhone demonstration

Open `FarmAssistant.xcodeproj`, select the shared `FarmAssistant` scheme and an iPhone Simulator, then Run. Deployment target is iOS 17; the project has no external iOS dependencies. Provider credentials belong only in the backend.

Start the backend using the root instructions. On first launch, enter `http://127.0.0.1:8787` and a separately provisioned **farmer session token**. The token is stored in the device Keychain; drafts and audio are stored in an owner-specific protected Application Support directory excluded from device backups. Do not enter an Anthropic or Sarvam API key into the app. Remote server addresses require HTTPS; HTTP is restricted in the client to loopback development addresses.

Select Tamil or English, speak a concern or farm description, or enter village and crop directly. When the backend returns proposed facts, explicitly select them and confirm the readback. Suggested coordinates are never copied from model output; only manually supplied coordinates can be confirmed. District and coordinates are optional, explicit fields: the app does not infer a village coordinate or pretend a manual coordinate is verified. Real weather requires confirmed coordinates until a reviewed village lookup is integrated. Further farm facts can be corrected in My Farm. My Farm → Language and audio changes the interface and the language used for new replies. Earlier replies and recordings keep their original language. Unknown fields stay absent.

The four native tabs are Today, Conversation, This Week and My Farm. Today presents the most recent response with its actual date, playback and reply. It does not relabel old responses as a fresh daily update. Each message exposes available evidence. Plans show separate approval, completion, postponement and rejection actions; decisions send the exact task version. Approval never performs an external farm operation.

Recording requests microphone permission only on use. Before upload, the farmer separately consents to remote audio processing. A recording lasts at most 29 seconds for the selected short-speech endpoint and supports preview, discard and explicit send. Original text and speech status remain visible if synthesis is unavailable. Submitted drafts retain retry IDs after ambiguous network outcomes. Closing the app stops recording and preserves the draft. Text entry is always available.

Authenticated server events trigger state refresh. The event stream resumes using the last application sequence and reconnects after interruptions; a failed stream falls back to periodic state refresh. Event listening runs only while the app is active. This is not a background push delivery mechanism. My Farm includes an explicitly labelled **local Simulator notification test**; no production APNs credential or delivery claim is included.

The app supports owner export and deletion endpoints. Exported data is private and remains in the protected app directory until account deletion or app removal. Server backup retention is a distinct policy. Signing out removes the current Keychain session; protected drafts remain for that session's later return.

## Verification

Use [the implementation status](../docs/verification/IMPLEMENTATION_STATUS.md) for current build and launch evidence. A successful simulator build does not validate microphone quality, Tamil comprehension, speech provider integration, source applicability, background notifications or physical-device operation. Tamil copy is a draft requiring native-speaker review. No fixtures or canned agent responses are embedded in this app.

Relevant APIs: [Apple streaming URLSession bytes](https://developer.apple.com/documentation/foundation/urlsession/bytes(for:delegate:)), [Apple microphone permission](https://developer.apple.com/documentation/avfaudio/avaudioapplication/requestrecordpermission(completionhandler:)).

Debug builds additionally accept `FARM_API_URL` and `FARM_SESSION_TOKEN` in the launch environment for a provisioned synthetic demo session. The token is saved to Keychain by the same validated setup path. Release builds do not read these environment variables. Do not put provider keys or session tokens into a shared Xcode scheme or source file.

Simulator Keychain requires the simulated application identifier generated by code signing. Build with signing enabled (the project default); for CLI demo builds use `CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-`. Do not use `CODE_SIGNING_ALLOWED=NO` for a runtime verification: that compiled but lacked the entitlement needed for secure Keychain writes. The signed build was installed and reached the language selection screen without a setup error on iPhone 17 Pro / iOS 26.2.
